צינור רכישה והקמת חשבון

איך עסקה שנסלקת בדף הבית הופכת לחשבון חי במערכת — עם המסלול הנכון, ההרשאות הנכונות, שעון הניסיון הנכון, ורישום מלא באדמין וב-CRM. מסמך אחד שמגדיר את חוזה הנתונים בין הסליקה, הפאנל והאנליטיקס.

כללי CTO — לא מתפשרים

  • ה-Webhook הוא מקור האמת היחיד. חשבון לא נפתח ולא משודרג על סמך redirect בדפדפן — רק על סמך קריאת שרת-לשרת חתומה מהסולק. דף התודה הוא שכבת אנליטיקס וחוויה בלבד.
  • Idempotency לפי txn_id. כל webhook יכול להגיע פעמיים — עיבוד כפול אסור שייצור חשבון כפול או חיוב כפול ב-CRM.
  • הרשאות נגזרות מטבלה אחת. אין if plan == 'educator' מפוזר בקוד — יש plan_entitlements אחת שכל המערכת קוראת ממנה.
  • כל אירוע חיוב נשמר גולמי. billing_events הוא יומן append-only — גם כשהעיבוד נכשל, האירוע נשמר וניתן לריפליי.
  • ייחוס שיווקי נוסע עם העסקה. ה-UTM שנתפס בדף הבית מגיע עד שורת הלקוח ב-CRM.

1זרימת הרכישה מקצה לקצה

1
דף הבית — בחירת מסלול clientהלקוח בוחר מסלול ומחזור חיוב. הדף כבר תופס UTM ראשוני ב-localStorage.wb_attr.
2
מעבר לסליקה client → cardcomהקישור לתשלום נושא: plan, billing, וה-attribution כשדות מטא של העסקה (custom fields). הסולק גובה או שומר טוקן ל-30 יום חינם.
3
Webhook שרת-לשרת cardcom → apiPOST /api/billing/webhook — אימות חתימה, רישום ב-billing_events, בדיקת idempotency.
4
שירות ההקמה (Provisioning) apiUpsert משתמש לפי אימייל → יצירת מנוי עם המסלול, המחזור ושעון הניסיון → צילום הרשאות מ-plan_entitlements.
5
הפעלת המערכת apiהחשבון נפתח עם ההרשאה הנכונה: תקרות תלמידים, אתרים, בורדי, משחקים, דומיין, API — הכול מהטבלה.
6
עדכון אדמין + CRM adminליד קיים עובר ל"לקוח", נוצרת שורת מנוי, מוני MRR ו-Trials מתעדכנים, התראה לצוות.
7
מייל ברוכים הבאים mailingסדרת onboarding לפי מסלול (קישור כניסה, סיור Walk Me, בורדי).
8
דף התודה clientהסולק מפנה ל-thank-you.html?plan=X&billing=Y&txn=Z — אירוע Purchase לפיקסל/Clarity/dataLayer + כפתור כניסה למערכת.

2חוזה הנתונים — PurchasePayload

המבנה הקנוני שכל צרכן במערכת מדבר בו. שכבת ה-webhook מתרגמת את הפורמט של הסולק (CardCom) לאובייקט הזה — ושאר המערכת לא מכירה את הסולק בכלל (החלפת סולק = החלפת מתרגם בלבד).

  "occurred_at": "2026-07-06T10:22:00+03:00",
  "customer": {
    "email": "dana@example.com",       // מפתח ה-upsert של המשתמש

שדות המטא בסליקה: בהקמת עמוד התשלום ב-CardCom מגדירים שדות custom‏ (plan, billing, utm_*) שמוזרקים לקישור מהדף — וחוזרים אלינו כלשונם ב-webhook. בלי זה אין ייחוס ואין זיהוי מסלול אמין.

5סכמת נתונים

-- יומן גולמי, append-only. מפתח ה-idempotency של כל הצינור.
CREATE TABLE billing_events (
  id            uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  txn_id        text UNIQUE NOT NULL,           -- מזהה הסולק
  event_type    text NOT NULL,                  -- purchase.completed / refund / ...
  processor     text NOT NULL DEFAULT 'cardcom',
  payload_raw   jsonb NOT NULL,                 -- הבקשה כפי שהגיעה
  processed_at  timestamptz,                    -- NULL = ממתין/נכשל, ניתן לריפליי
  error         text,
  created_at    timestamptz DEFAULT now()
);

CREATE TABLE subscriptions (
  id                 uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id         uuid REFERENCES accounts(id) NOT NULL,
  plan               text NOT NULL,             -- trial|teacher|educator|leader|enterprise
  billing_cycle      text NOT NULL,             -- monthly|yearly|none
  status             text NOT NULL,             -- trialing|active|past_due|cancelled|grace
  trial_ends_at      timestamptz,
  current_period_end timestamptz,
  processor_token    text,                       -- טוקן חיוב חוזר
  created_at         timestamptz DEFAULT now()
);

-- צילום הרשאות לחשבון (נכתב בהקמה/שדרוג; המערכת קוראת רק מכאן)
CREATE TABLE account_entitlements (
  account_id    uuid PRIMARY KEY REFERENCES accounts(id),
  students_cap  int, courses_cap int, sites_cap int,
  flags         jsonb NOT NULL,                 -- {"boardi.create":true,"games":true,...}
  snapshot_from text NOT NULL,                  -- המסלול שממנו צולם
  updated_at    timestamptz DEFAULT now()
);

-- ייחוס שיווקי — first-touch מהדף, נקשר ללקוח ב-CRM
CREATE TABLE attribution_touches (
  id          uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  account_id  uuid REFERENCES accounts(id),
  utm         jsonb,                             -- source/medium/campaign/content/term
  referrer    text, landing text,
  first_seen  timestamptz
);

plan_entitlements (טבלת האמת מסעיף 3) היא טבלה סטטית קטנה שמנוהלת במיגרציות — שינוי תמחור/הטבות עובר קוד-ריוויו, לא עריכה ידנית.

6Webhook והקמה — סדר הפעולות

POST /api/billing/webhook
// 1. אימות: חתימת HMAC של הסולק + IP allowlist. כשל = 401, בלי רישום.
// 2. תרגום: payload של הסולק → PurchasePayload קנוני.
// 3. רישום: INSERT INTO billing_events (txn_id UNIQUE).
//    conflict on txn_id? → 200 OK מיד (idempotent, כבר טופל).
// 4. עיבוד (בטרנזקציה):
//    a. upsert user לפי email (חדש? → הזמנה + סיסמה ראשונית)
//    b. upsert account + subscription (plan, billing, status, שעונים)
//    c. צילום הרשאות: plan_entitlements → account_entitlements
//    d. attribution_touches ← attribution מה-payload
//    e. CRM: ליד לפי email? move stage → "לקוח" ; אחרת contact חדש
//    f. תור מיילים: welcome sequence לפי plan
//    g. audit_log + התראת אדמין
// 5. סימון processed_at. כשל בעיבוד? האירוע נשאר ביומן → retry ברקע.
// 6. תשובה 200 תמיד אחרי שלב 3 (לא מפילים retry של הסולק על באג פנימי).

9חיבור דף התודה (כבר בנוי)

ה-Success URL בסולק מפנה אל:

https://[domain]/thank-you.html?plan=educator&billing=yearly&txn=CC-8412734&value=1990

הדף מזהה את העסקה ומציג כרטיס מותאם למסלול, ויורה — פעם אחת בלבד לכל txn — את אירועי השיווק: Purchase לפיקסל (עם הסכום המדויק), StartTrial לניסיון, Lead לארגוני, תיוג Clarity, ו-purchase_completed ל-dataLayer עם הייחוס המלא. כפתור "כניסה למערכת" מוביל ל-https://whiteboard.education/.

הפרדת אחריות: דף התודה = שיווק ומדידה. ה-webhook = הקמה והרשאות. גם אם הלקוח סגר את הדפדפן לפני דף התודה — החשבון שלו נפתח.
